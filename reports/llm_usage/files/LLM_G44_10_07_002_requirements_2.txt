"Technical Design Document – feature_selection.py

This document is derived strictly from the project specification contained in Progetto_ISW_2025-26_specifiche.pdf. Where the specification is explicit, it is treated as authoritative. Where ambiguity exists, it is explicitly identified rather than resolved by inventing alternative formulations.

SECTION 1 – Formal Problem Definition
1.1 Purpose

The purpose of feature_selection.py is to:

Read the normalized dataset.
Build a QUBO feature-selection problem.
Optimize the QUBO repeatedly while varying α.
Obtain approximately the desired number of selected features.
Generate reduced training and test datasets.
Save optimization statistics and outputs.
1.2 Input Data

Input dataset:

UU

where:

rows = samples
columns = features

and

VV

is the binary target vector.

The module receives:

normalized CSV
target column name
desired feature percentage
tolerance allowance
test-set percentage
random seed
maximum number of alpha evaluations (alpha_computations)
1.3 Output Data

Primary output:

X∗X^*

Binary selection vector:

X∗=[x1,x2,…,xn]X^*=[x_1,x_2,\dots,x_n]

where:

xj=1x_j=1 → feature selected
xj=0x_j=0 → feature removed

Additional outputs:

reduced training dataset
reduced test dataset
optimization history CSV
feature-selection JSON report
1.4 Optimization Objective

The specification states:

select features that are strongly correlated with the target and weakly correlated with each other.

Therefore the objective combines:

Influence

Feature-target relevance.

Higher correlation with target is desirable.

Independence

Feature-feature redundancy.

Higher feature-feature correlation is undesirable.

1.5 Role of Alpha

The specification defines:

0≤α≤10 \le \alpha \le 1

with:

α = 0 → no features selected
α = 1 → all features selected

Alpha regulates the balance between:

influence term
independence term

The required number of selected features must be obtained exclusively by changing α.

No cardinality constraint may be added to the QUBO.

1.6 Role of Influence

Influence quantifies:

∣ρVj∣|\rho_{Vj}|

where:

feature jj
target vector VV

A large value means feature jj contains information useful for predicting the target.

1.7 Role of Redundancy

Redundancy quantifies:

∣ρjk∣|\rho_{jk}|

between pairs of features.

Large values indicate duplicated information.

The optimization penalizes simultaneous selection of highly correlated features.

SECTION 2 – Mathematical Breakdown
2.1 Spearman Feature-Target Correlations

For every feature:

ρVj\rho_{Vj}

must be computed using Spearman correlation.

Reason:

The specification explicitly chooses Spearman because it does not assume linear relationships.

2.2 Spearman Feature-Feature Correlations

For every feature pair:

ρjk\rho_{jk}

compute Spearman correlation.

This generates a full pairwise correlation structure.

2.3 Absolute Value Handling

The specification explicitly requires:

∣ρVj∣|\rho_{Vj}|

and

∣ρjk∣|\rho_{jk}|

not signed correlations.

Consequences:

strong negative correlation is treated as informative
strong positive correlation is treated as informative
both contribute equally in magnitude
2.4 Diagonal of Q

The appendix explicitly states:

terms α xj |ρVj| are placed on the diagonal.

Therefore:

QjjQ_{jj}

contains the influence contribution associated with feature jj.

2.5 Off-Diagonal Elements

The appendix states:

terms −(1−α)|ρjk| are elements of row j column k.

Therefore:

QjkQ_{jk}

captures redundancy penalties.

2.6 Alpha Effect

Increasing α:

increases influence importance
reduces independence importance
generally increases selected features

Decreasing α:

strengthens independence pressure
discourages selection
usually leads to fewer selected features
SECTION 3 – Q Matrix Construction Strategy
3.1 Inputs

Input:

normalized feature matrix UU
target vector VV
3.2 Output

Output:

Q∈Rn×nQ \in \mathbb{R}^{n \times n}

where nn is the number of features after preprocessing.

3.3 Dimensions

If:

n=145n = 145

then:

Q=145×145Q = 145 \times 145

If:

n=500n = 500

then:

Q=500×500Q = 500 \times 500

etc.

3.4 Symmetry

Because:

∣ρjk∣=∣ρkj∣|\rho_{jk}| = |\rho_{kj}|

the off-diagonal structure is symmetric.

Therefore:

Qjk=QkjQ_{jk}=Q_{kj}

for all feature pairs.

SECTION 5 – Alpha Search Design
Requirement

Specification explicitly states:

vary α repeatedly
obtain desired K
do not encode K inside QUBO
Target

Expected features:

K=round(percSelected⋅n)K = round(percSelected \cdot n)

Acceptance:

K±allowanceK \pm allowance
Candidate Strategies
Linear Search

Advantages:

simple
deterministic

Disadvantages:

may waste iterations
poor efficiency
Binary Search

Advantages:

logarithmic convergence

Disadvantages:

Requires monotonic behavior.

The specification suggests feature count generally increases with α, but does not mathematically guarantee strict monotonicity.

Therefore binary search may occasionally fail.

Adaptive Search

Procedure:

Start α = 0.5
Evaluate
Compare selected count with target
Move upward or downward
Reduce step size progressively
Stop when tolerance achieved

Advantages:

robust to slight non-monotonicity
fewer evaluations than linear search
safer than strict binary search
Recommended Approach

Adaptive binary-style search.

Stopping Criteria

Stop if:

Criterion 1

Desired range reached:

K−allowance≤nselected≤K+allowanceK-allowance \le n_{selected} \le K+allowance
Criterion 2

Maximum alpha evaluations reached.

iterations=alpha_computationsiterations = alpha\_computations
Criterion 3

Repeated identical outcomes.

Handling Oscillation

Possible:

17 features
21 features
18 features
22 features


Strategy:

Return best solution encountered.

Best = minimum distance from target K.

Handling Non-Convergence

If limit reached:

Return:

closest solution found
corresponding alpha
full optimization history

This respects specification and avoids infinite loops.

6.4 Correlation Bottleneck

Most expensive operation:

O(n2m)O(n^2m)

6.5 Optimization Bottleneck

Dense QUBO optimization repeated many times.

Cost:

alpha_computations×solver_runtimealpha\_computations \times solver\_runtime
Recommended Efficiency Measures
Read only once.
Keep feature matrix numeric.
Avoid dataframe copies.
Reuse correlation matrices.
Build correlations once.
Rebuild Q from cached correlations only.
Store optimization statistics incrementally.

SECTION 10 – Final Recommendation

The safest implementation strategy consistent with the specification is:

Load normalized dataset.
Separate target column.
Compute all Spearman feature-target correlations once.
Compute all Spearman feature-feature correlations once.
Cache both structures.
For every alpha evaluation:
construct dense Q matrix from cached correlations
run simulated annealing
obtain binary vector
count selected features
Use adaptive alpha search.
Stop when target K ± allowance is achieved or when alpha_computations is exhausted.
Retain the closest solution encountered.
Save:
optimization history CSV
final JSON report
reduced training dataset
reduced test dataset
Ensure strict compliance with:
required function signature
required JSON schema
required CSV outputs
first-M-row split rule
no cardinality constraint in QUBO
seed-controlled reproducibility.

From an engineering perspective, the highest-risk area is alpha search behavior, not QUBO construction. The Q matrix formulation is explicitly defined in the appendix, whereas the search procedure is intentionally left open. Therefore, the implementation should prioritize a deterministic, reproducible, and well-documented adaptive alpha search that always returns the closest feasible feature count while respecting the alpha_computations limit."
