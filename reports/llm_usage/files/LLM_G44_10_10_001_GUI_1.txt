1. Technology Evaluation
Candidate Technologies
Tkinter

Advantages

Included with standard Python distributions.
No additional dependencies required.
Works offline.
Easy portability across Windows, Linux, and macOS.
Aligns well with academic project distribution requirements.
Simple deployment for professors evaluating the project.

Disadvantages

Older visual appearance.
More manual work for modern layouts.
Limited built-in visual components.
Streamlit

Advantages

Extremely fast development.
Modern web-based interface.
Excellent support for displaying tables and metrics.

Disadvantages

Requires additional installation.
Launches a local web server.
More complex project execution workflow.
Less suitable if evaluators expect a traditional desktop application.
Gradio

Advantages

Very quick to develop.
Good support for machine-learning workflows.
Clean interface.

Disadvantages

Additional dependency.
Primarily designed for ML demonstrations.
Less appropriate for multi-step file processing pipelines.
PyQt

Advantages

Professional appearance.
Rich widget ecosystem.
Excellent scalability.

Disadvantages

Large dependency.
Significantly more implementation effort.
Increased packaging complexity.
Evaluation Summary
Criterion	Tkinter	Streamlit	Gradio	PyQtInstallation	Excellent	Medium	Medium	Poor
Dependencies	None	External	External	Large
Portability	Excellent	Good	Good	Good
Development Speed	Good	Excellent	Excellent	Medium
Academic Evaluation	Excellent	Good	Good	Medium
Reproducibility	Excellent	Good	Good	Good
Recommended Technology
Tkinter
Justification

Tkinter is the most appropriate choice because:

It is included with Python.
Requires no additional installation.
Provides deterministic execution.
Simplifies evaluation by professors.
Fully satisfies project requirements.
Reduces dependency-related risks.

The GUI is an orchestration layer, not a visualization-heavy analytics platform. Therefore Tkinter provides sufficient functionality while minimizing complexity.

Backend Integration Strategy

GUI never reimplements:

Plain Text
fit_normalize
select_features
train

It only:

Collects input parameters.
Calls backend APIs.
Displays results.
Displays generated artifacts.
Handles errors gracefully.

This architecture minimizes duplication, maximizes maintainability, and aligns with both the project specification and the existing backend implementation.
