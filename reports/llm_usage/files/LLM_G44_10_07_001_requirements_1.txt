Section 1 – Executive Summary

The project consists of building a complete Python application for binary classification on large tabular datasets with an intermediate QUBO-based feature selection stage.

The system must:

Read a CSV dataset.
Remove low-quality features.
Normalize all numerical features using z-score normalization.
Split the dataset into training and test subsets.
Perform feature reduction using a QUBO optimization model based on Spearman correlations.
Train one of three classification algorithms.
Save the trained model.
Evaluate the model on the test set.
Export predictions and quality metrics.
Expose both:
Python API functions
CLI commands
GUI interface
Include automated tests and reproducibility guarantees.

The final implementation must be scalable enough to process datasets up to 1.5 million+ rows.

Section 2 – Functional Requirements
FR-1 Dataset Input

The system must:

Read CSV files.
Detect header row.
Accept the target column name as input.
Support binary targets encoded as 0/1.
Support any number of rows and features.
FR-2 Preprocessing

The preprocessing phase must:

Load dataset.
Separate target column.
Detect empty/almost-empty features.
Remove features below threshold.
Normalize all remaining features.
Preserve target column.
Produce normalized CSV.
Produce preprocessing JSON report.
FR-3 Feature Removal

A feature must be removable when it contains:

too many missing values
too many zero values

Threshold supplied by user. Example: 95%.

FR-4 Normalization

Must perform:

z-score standardization
mean = 0
standard deviation = 1

Target column excluded.

FR-5 Dataset Split

Must:

Compute M from test percentage.
Use first M rows as training set.
Use remaining rows as test set.
Perform hard split (no shuffle).
Save both datasets.
FR-6 QUBO Feature Selection

Must:

Construct QUBO matrix.
Use Spearman correlations.
Use influence term feature-target.
Use redundancy term feature-feature.
Use parameter α ∈ [0,1].
Optimize repeatedly varying α.
Find K selected features within tolerance.
Produce binary solution vector.
Save optimization history.
Save feature selection JSON report.
FR-7 Feature Reduction

Must:

Apply selected feature mask.
Generate reduced training dataset.
Generate reduced test dataset.
Keep target column.

Section 6 – QUBO Analysis
Spearman Correlations

Specification requires Spearman correlations because they do not assume linear relationships.

Two correlation families are required:

Feature ↔ Target
ρVj\rho_{Vj}

Measures influence of feature j on target.

Absolute value used.

Feature ↔ Feature
ρij\rho_{ij}

Measures redundancy between features.

Absolute value used.

Feature-Target Influence

Encourages selecting features strongly correlated with target.

Higher correlation:

lower objective value
greater chance of selection

according to specification formulation.

Feature-Feature Redundancy

Penalizes selecting highly correlated feature pairs.

Goal:

maximize information
reduce redundancy.
Alpha Parameter
0≤α≤10 \le \alpha \le 1

Behavior:

α = 0 → no features selected
α = 1 → all features selected

Specified explicitly.

Search Strategy for Alpha

Required:

Build QUBO for α.
Optimize.
Count selected features.
Compare with target K.
Adjust α.
Repeat.
Stop when:
target K ± allowance reached


or

alpha_computations exceeded


QUBO must NOT explicitly constrain cardinality K. Alpha search is mandatory.

Output Binary Vector

Output:

x*


Example:

[1,0,0,1,1,0,...]


Meaning:

1 = selected
0 = excluded


Length equals number of features after preprocessing.

Section 8 – Risk Analysis
Technical Risks
QUBO Solver Scalability

Dense Q matrix:

145 x 145 initially


Can become computational bottleneck.

Spearman Computation Cost

Requires pairwise correlations.

Complexity grows quadratically with feature count.

Memory Consumption

1.5M-row datasets may stress RAM.

Performance Risks
Full dataframe duplication.
Recomputing correlations.
Excessive alpha iterations.
Inefficient CSV IO.
Evaluation Risks

Highest-risk failures:

Wrong repository tree.
Missing mandatory functions.
Wrong function signatures.
Wrong CLI commands.
Wrong JSON schemas.
Wrong prediction CSV format.
Missing tests.
No saved model.
Not using QUBO.
Incorrect alpha search.
Common Implementation Mistakes
Data Leakage

Forbidden:

fit scaler on test data
train on test data
use target incorrectly

Explicitly penalized.

Cardinality-Constrained QUBO

Specification explicitly forbids imposing exact K in objective.

Must search via α.

Incorrect Split

Must use:

first M rows → train
remaining rows → test


No random split.
